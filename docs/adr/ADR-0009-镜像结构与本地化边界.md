# ADR-0009 · 镜像结构与本地化边界

> **Status**：Accepted（2026-11-15 聚合定稿；结构惯例部分被 D-065 收窄）
> **覆盖决策**：D-037、D-038、D-045、D-046
> **相关**：`ADR-0007`（禁机翻）、`格式规范与要求.md` §十八

## Context

四语镜像（`en_us` / `zh_tw` / `ja_jp` / `ko_kr`）不是「把 `zh_cn` 全量翻译一遍」，而是「对齐结构的平行副本」。落地时反复遇到三个问题：

1. **文件名要不要转语言**——转了就与 `zh_cn` 的双链对不上；
2. **哪些类别根本不可建**——正文全为自撰中文（`rules/`、`货币战争/`）时，翻译即触禁令；
3. **音乐类目的特殊性**——曲目名是可穷举的官方事实，与「正文」不同。

## Decision

1. **镜像结构惯例**（D-037）：目录层级与文件名**保持中文原样不转换**；章节标题 / 表格表头 / 正文转目标语言；元信息行标签保持简体（`> 数据来源：` `> 数据版本：` `> 实体ID：`）；双链目标路径保持简体；四语镜像与 `zh_cn` 逐文件同构。
2. **可建性分级**（D-038）：按「是否存在官方本地化文本」把类别分三档——可建（全文）、部分可建（仅事实表）、不可建（正文为自撰中文）。不可建类别永久只保留 `zh_cn`（及已有的 `zh_tw`），不强行补。
3. **音乐类目单列**（D-045 / D-046）：曲目名属官方事实，允许跨语言建「曲目」节（节名随语言：`## Tracks` / `## 収録曲`），逐条照抄官方目录，禁机翻、禁改写标点 / 大小写 / 重排；取证源分级为
   EN / JA → Apple 官方目录接口；KO → Naver Vibe 官方接口；取不到即不建节并登记。
4. **镜像不是翻译任务的产物**：任何镜像文件的正文若无法指向官方本地化原文，按 ADR-0007 写「待补充」，不生成内容。

## Consequences

- **正面**：双链在四语间稳定可用；新增类别时有明确的可建性判据，不再逐次争论。
- **负面**：`zh_cn` 有一批类别永远不会有完整镜像，规模数字呈现不对称。
- **风险**：D-045 曾以「用户拍板」临时放宽过「不得写曲目清单」的口径；此类放宽只对音乐类目生效，不得外推到其它类别。
