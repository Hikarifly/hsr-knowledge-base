# ADR-0004 · 版本基线、文档时效与日志规范

> **Status**：Accepted（2026-11-15 聚合定稿）
> **覆盖决策**：D-004、D-056、D-069、D-072
> **相关**：`数据来源.md`、`update.md`、`docs/metrics.md`

## Context

版本号是文档里最容易腐烂的字段。盘点实测：README 写 4.7，`数据来源.md` 写 4.6，`遗器规则.md` 写 4.5，同一时间点三套基线并存；`update.md` 里还有一批指向外部的链接，违反「更新日志不放链接」的既定准则。
同时，每次版本入库都会带来新的执行口径（schema、镜像范围、前置修复），若不写死，下一版又会重新讨论。

## Decision

1. **基线口径统一**：每次版本更新同时钉死三件事——数据基线版本、内容收录日期、文档口径统一日期（D-004 的 4.6 版即此形态；4.7 为「基线 4.7 / 收录 2026-11-11 / 文档口径 2026-11-15」）。
2. **4.7 的四项执行口径**（D-056，作为后续版本模板）：
   - 遗器 schema：位面饰品只有二件套时，保留 `### 4 件套` 节并置 `-`（与库内 28/29 个既有位面饰品一致）；
   - 镜像范围：按版本分批，4.7 只做 `zh_cn` + `en_us`，其余三语后置并登记；
   - 前置修复：先修索引计数漂移与空 H1 残文件，再开工新内容；
   - 开工基线：未提交改动先提交，作为回滚点。
3. **历史文档冻结而非回填**：`数据来源.md` 回填当前基线；`遗器规则.md`（4.5）、`docs/SRR_ID对照报告.md`（4.6）加头部 `> 状态：历史文档（冻结于 X 版，仅供溯源，数字不再维护）`，本体不回填（D-069）。
4. **更新日志禁链接**：`update.md` 只写纯文本路径，不写 URL / 双链；时间精确到分钟；现存违规行在结构搬迁时一并改为纯文本（D-072）。

## Consequences

- **正面**：版本到期只需替换三个字段；历史文档不再被误当现行规范；日志可全文检索且无外链失效风险。
- **负面**：冻结文档与现行规范存在数字差，读者需注意头部状态行。
- **风险**：基线更新若漏改 `docs/metrics.md`，`verify_site[16]` 会直接把构建判为 FAIL——这是有意设计（见 ADR-0011）。
