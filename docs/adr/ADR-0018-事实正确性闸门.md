# ADR-0018 · 事实正确性闸门

> **Status**：Accepted（2026-11-15）
> **覆盖决策**：D-078
> **相关**：`docs/ROADMAP.md` 主线 E、`docs/专名对照表.md`、`ADR-0011`（真值口径）

## Context

PR #1 并入后，四项验收（site / fields / links / docs）长期全绿，但**「设定本身对不对」没人核对**：直到 2026-11-15 才发现 `绒韬将军` 应为 `戎韬将军`、方壶/玉阙被镜像误标「已陨/失踪」、诛罗遗漏、公司 P47 级被当噪声删除（见 issue #23）。根因：**格式合规 ≠ 事实正确**，既有验收器全部只看结构与数字，没有一条看「内容与官方源是否一致」。
ROADMAP 据此新增主线 E，但 E1–E4 只是口号——「抽查 20 条」没说谁跑、怎么抽、登记在哪。

## Decision

1. **E4 抽检随版本收口跑**（主 A4 增加一步）：抽检对象 = 本版改动条目 + 随机 10 条旧条目；结果与差异清单写进**当版收口 issue**；不设独立周检（无专职维护者时必然荒废）。
2. **E1 粒度 = 设定性内容段级标来源**：世界观 / 剧情 / 社区投稿等叙述性段落逐段给出处；数据文件已有头部 `> 数据来源：` 元信息，**不重复加**，避免双处维护。
3. **存量只回溯高危区**：即社区投稿并入的段落（PR#1 类，已发生过事实错误处）；其余存量靠 E4 每版滚动抽检逐步覆盖。不做全量回溯——大部分段落无源可标，会产生大量「待核实」噪音。
4. **B 线负向指标进真值表**：`labeled_nonofficial_{en_us,zh_tw,ja_jp,ko_kr}` 4 个 key 进 `docs/metrics.md`（由 `gen_metrics.py` 生成），`verify_site[16]` 将其纳入必填 key——「打标文件数只减不增」从此可机械校验。
5. **E2 专名对照表独立成文**：`docs/专名对照表.md`（将军名号 / 天才俱乐部编号 / 公司 P 级等专名 × 五语 × 官方源）；它是对账**产物**不是术语，不进 GLOSSARY。

## Consequences

- **正面**：「正确性」从口号变成绑定版本节奏的机械步骤；打标规模进入唯一真值表，负向趋势可追踪。
- **负面**：每次版本收口多一步抽检（预计 30–60 分钟）；新 世界观 内容写作时要多写出处行。
- **风险**：抽检依赖「权威源」可得性——官方文本未覆盖的条目只能标「待核」，抽检报告需区分「确证错误」与「无源待核」两类，前者当版修复，后者登记台账。
