# ADR-0013 · 批量写入与操作安全

> **Status**：Accepted（2026-11-15 聚合定稿）
> **覆盖决策**：D-031、D-032、D-033、D-034、D-042、D-061
> **相关**：`ADR-0001`（执行方）、`协作要求与行动准则.md` §七

## Context

本库的批量操作以「万级文件」为单位（时间戳 30,018 个 `.md`、镜像 23,049 个、撤下 836 个）。这类操作一旦脚本写错，损失是整批而非单文件。已发生的四类事故：

1. **时间戳污染**：写文件本身改变 mtime，直接把「维护时刻」写成「更新时间」，且污染不可逆（须先有 stamp 前备份）。
2. **逐行删除误伤**：用「按前缀删行」清理时间戳，把文档代码块里的示例行 `> 创建时间：YYYY-MM-DD HH:mm` 一起删了／被改写。
3. **ACL 拒写伪装成卡死**：受限令牌对数据目录拒写，`robocopy` 默认百万次重试，表现为「卡住 20 分钟」。
4. **整文件重写丢节**：执行方为「回填曲目」而整体重写专辑文件，两次丢失 `## 关联条目` 节（由 `verify_fields` 捕获）。

另有一次**判断性错误**（D-061）：Lead 把四个镜像里的 `_冰_五星.md` 判为空壳删除，实际各含 54 行有效内容，只能用 `git show <commit>^:<path>` 取回。

## Decision

1. **先备份再批量**：任何万级写操作前建立可追溯备份（`.tmp_build/…_backup/`），并验证备份条目数；还原路径必须在开工前写清（D-031 / D-033）。
2. **只改指定节 / 行**：批量改写不得整文件重写；脚本必须围栏感知（代码块内不动），对不认识的既有时间戳行（`> 生成时间：` 等）保留并报警（D-032 / D-042）。
3. **撤时间戳用 `git restore`**：本地规范优先于脚本；需要「撤销」时回到版本库状态，而不是用删除脚本反推（D-032）。
4. **批量工具显式限重试**：文件复制 / 移动一律显式 `/R:<n> /W:<s>`；出现 `ERROR 5 (0x00000005)` 即判定权限问题，先修 ACL 再重跑，不得当成慢（D-034）。
5. **删除前必须读全文**：判定「空壳 / 无内容」前必须统计非空行数并抽读，**不得**只凭 H1 或角色名为空下结论；删除后保留可回溯的 commit 路径（D-061）。
6. **进度即存**：长批次按文件粒度落盘，中途中断可续；禁止「全部算完再一次性写」。

## Consequences

- **正面**：事故可还原；批量改动可被 `git diff --stat` 与备份条目数双重核对。
- **负面**：批处理流程变长（备份 + 围栏 + 限重试 + 逐文件落盘）。
- **风险**：备份目录本身在 `.gitignore` 内，不能当作长期归档；超过一个版本周期的备份应有替代证据（提交历史）。
