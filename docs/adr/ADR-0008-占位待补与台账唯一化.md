# ADR-0008 · 占位、待补与台账唯一化

> **Status**：Accepted（2026-11-15 聚合定稿）
> **覆盖决策**：D-008、D-060、D-070
> **相关**：`docs/待补充清单.md`、`待办清单.md`、`ADR-0004`

## Context

「缺数据」是本库的常态，但历史上有三种处理方式并存：建空占位条目、写「待补充」、写「未取得」。结果是同一状态有多种词、台账有两份（`docs/待补充清单.md` 与 947 项的 `待办清单.md`），无法回答「到底还缺多少」。
实测口径也支持收敛：库内「待补充」544 个文件 vs「未取得」31 个，且 `relic/隧洞遗器/戏梦点星的伶人.md` 已有「描述：待补充」先例。

## Decision

1. **不建占位 / 空条目**：拿不到字段就不建文件；已建文件缺字段时登记台账（D-008）。
2. **标注词唯一**：一律写「**待补充**」（英 Pending / 日 未収録 / 韩 미수록）；「未取得」不再是合法状态词（D-060）。
   - 禁止编造 ID：无官方 ID 写 `> 实体ID：无（官方未公开）`，索引文件写「不适用」。
3. **台账唯一**：`docs/待补充清单.md` 是**唯一现行台账**；`待办清单.md`（947 项，2026-08-28 快照）标「历史快照，勿新增」，其内容按七主题迁入 `docs/backlog/`；两份文件都不删除（D-070）。
4. **登记即闭环**：写入台账的条目须带「文件 / 字段 / 已确认的依据 / 补全所需来源」；能靠官方源当轮补齐的，不留到台账。

## Consequences

- **正面**：「缺什么」可被脚本统计（`verify_fields` 的待补充数）；台账与 issue 各司其职（内部台账 vs 对外可追踪）。
- **负面**：历史快照与新台账并存，读者需注意 `待办清单.md` 已冻结。
- **风险**：状态词统一后，旧文件里的「未取得」需要一次全量替换才能让统计准确——4.7 的 13 个新文件已完成（37 处），`音乐/` 与 `货币战争/赛季更新.md` 的存量尚未纳入。
